# SIGROOM — บันทึกส่งมอบ M2

วันที่: 24 ส.ค. 2569

## สิ่งที่ทำ

- เพิ่มหน้าเข้าสู่ระบบ ปฏิทินหน้าแรก ค้นหาห้องว่าง ฟอร์มจอง รายละเอียด การแก้ไข/ยกเลิก และรายการจองของฉัน
- ปฏิทินแสดงวัน/สัปดาห์/เดือน ภาษาไทยและ พ.ศ. พร้อมสีสถานะและแถบเวลาเตรียม/เก็บห้อง
- ค้นหาห้องรวม buffer สิทธิ์หน่วย เวลาให้บริการ ระยะจอง ความจุ และการชนของอุปกรณ์ส่วนกลาง
- ฟอร์มรองรับบันทึกร่าง/ส่งคำขอ รายการค่าที่หน่วยเคยใช้ และส่งต่อวัน เวลา จำนวนคน และอุปกรณ์จากหน้าค้นหา
- การส่งคำขอยังใช้ exclusion constraint ของ M1 เป็นด่านสุดท้าย หากมีคนจองตัดหน้า ข้อมูลในฟอร์มไม่หาย
- เพิ่มการมองเห็นแบบเต็ม/ปกปิด ยกเลิกก่อนเส้นตาย แก้เฉพาะรายละเอียดหลังส่ง และคำขอเร่งด่วนสำหรับห้องที่ต้องอนุมัติ
- เพิ่มบัญชีทดลองผ่าน `seed_pilot --demo-users`: `somchai` (COMM) และ `wanida` (EW)
- เก็บ Pico CSS, FullCalendar และ HTMX ไว้ใน `static/vendor/` จึงใช้งานใน LAN ได้โดยไม่เรียก CDN

## Schema

- เพิ่ม `Booking.equipment` เป็น Many-to-Many ไปยังอุปกรณ์ส่วนกลาง ผ่าน migration `0002_booking_equipment.py`
- ไม่แก้ `BookingResource`, exclusion constraint, `compute_hold`, `place_holds`, `release_holds` หรือ `approval_policy_for`

## การตรวจรับ

- `pytest`: ผ่าน 19 ข้อ (M1 เดิม 9 + M2 ใหม่ 10)
- `manage.py check`: ไม่พบปัญหา
- `makemigrations --check --dry-run`: ไม่มี migration ค้าง
- เปิดตรวจหน้าจอจริงครบหน้าเข้าสู่ระบบ ปฏิทิน ค้นหาห้อง ฟอร์มจอง และการจองของฉัน
- การตรวจภาพจริงทำให้แก้ธีมมืดที่ทำให้ตัวอักษรกลืนพื้นหลัง และแก้การส่งต่อวัน/เวลา/จำนวนคนจากหน้าค้นหา

## ข้อจำกัดที่ตั้งใจไว้ใน M2

- การอนุมัติ/ปฏิเสธจะทำใน M3
- การจองที่ส่งแล้วเปลี่ยนเวลา ห้อง หรืออุปกรณ์ส่วนกลางไม่ได้ ต้องยกเลิกแล้วจองใหม่จนกว่าจะมี amendment ใน M5
- การนับความเร่งด่วนใช้วันทำการจันทร์–ศุกร์ ยังไม่รวมวันหยุดส่วนกลาง (จะเพิ่มใน M4)
- รูปลักษณ์เน้นเรียบและสม่ำเสมอ การขัด UX/UI รอบสุดท้ายอยู่ใน M6

## วิธีดูผลด้วยตา

1. รัน `uv run manage.py migrate`
2. รัน `uv run manage.py seed_pilot --demo-users`
3. รัน `uv run manage.py runserver`
4. เปิด <http://127.0.0.1:8000/> แล้วเข้า `somchai` หรือ `wanida` ด้วยรหัสผ่านทดลองที่ระบุในแผน M2

# PR-2 เมนูตามบริการ

ฐานจริง `feat/lodging-v5-2` ที่ `9d57b9c` รวม PR #87 แล้ว Branch `feat/service-shell` ไม่มี rebase หรือ force-push งานค้างใน checkout หลักและ PR #82 คงไว้

เมนูคอมและมือถือใช้ include เดียว สังกัดบริการมาจาก route ที่ resolve แล้วและหมวดห้องจริง ไม่เชื่อ header รายการส่วนตัวกรองทั้งการจองเดี่ยวและชุดการจอง ลิงก์แท็บและลิงก์กลับรักษาหมวดเดิม ผลค้นหาจากแฟ้มห้องเรียน/ประชุมล็อกหมวด แฟ้มห้องพักกดทั้งใบเข้า `lodging_start` และใช้คำข้าราชการทหาร เส้นทางคำขอนี้ยังเป็นสาธารณะ

ตรวจ source และ diff ทั้งหมดแล้ว ไม่มีการแก้กฎอนุมัติ สิทธิ์ผู้จอง/เจ้าหน้าที่ หรือ constraint จองซ้อน การทดสอบเต็มโดยผู้ตรวจแยกจากผู้เขียน: **978 passed, 444 warnings, 132.13s** บน Python 3.12.10 และ PostgreSQL local แยกชื่อ `sigroom_online_beta_qa` ผู้เขียนตรวจ targeted 155 ข้อ, Django check ไม่มีปัญหา, migration drift ไม่มี, Node 10 ข้อผ่าน และ diff check ผ่าน

Browser QA จริงที่ 1280×900 และ 390×844 ด้วยครูจำลอง: แฟ้มทั้งสี่เข้าเมนูบริการเดียวกัน ลิงก์บริการทั้งหมดกลับได้ เปลี่ยนเวลายังได้ห้องเรียน รายการของฉันจากห้องประชุมมีเพียงห้องประชุม ลิงก์ข้าราชการทหารเข้าแบบเดิมได้ ไม่มีจอล้นหรือ console error เจ้าหน้าที่จำลองยังมีคิวอนุมัติ การใช้งาน จัดการที่พัก และรายงานทั้งสองขนาด ตรวจและซ่อมการตัดบรรทัดเมนูปฏิบัติการบนมือถือ ภาพจริงอยู่ `docs/qa/online-beta/pr2/`

Test เดิมที่ปรับตาม runbook: `tests_lodging_about_r3g2.py`, `tests_lodging_service_gateway.py`, `tests_task_first_a2_gateway.py`, `tests_ux17_showcase.py`, `tests_ux20_lodging_about.py` (สองข้อ), `tests_ux28_operations.py` เพื่อให้ตรวจลิงก์แฟ้มทั้งใบและเส้นทางสองแบบจากหน้าถัดไป

เพิ่มตามคำอนุญาตล่าสุด: `tests_gateway_navigation.py` (สองข้อ), `tests_task_first_a5_lodging.py` (หนึ่งข้อ), `tests_ux1.py` (สามข้อ), `tests_ux32_booking_v2.py` (หนึ่งข้อ) เปลี่ยนข้อความ/เมนูเก่าเป็นเมนูบริการเดียว ยังคงและเพิ่มการตรวจ guest login, สิทธิ์ปฏิบัติการ และลิงก์จริงทั้งสองขนาด ไม่ลบหรือ skip ข้อใด เพิ่ม `tests_service_shell.py` ครอบคลุมทุกชื่อ route และการกรอง/สิทธิ์/ลิงก์ต่อเนื่อง

ข้อสงสัย:

- ยังไม่มีหน้ารวมสถานะคำขอที่พักแบบสาธารณะที่ปลอดภัย ลิงก์สถานะคำขอจึงแสดงเฉพาะเมื่อเปิดสถานะด้วย token ของคำขอนั้น ไม่รวมหรือเปิดเผย token ผู้อื่น
- ทาง legacy `/book/` ที่ไม่ระบุหมวดคงตัวเลือกเดิม การเปลี่ยนหมวดผ่าน HTMX อัปเดตผล แต่หัวเรื่อง/เมนูเปลี่ยนเมื่อเปิดหน้าเต็ม ทางเข้าแฟ้มทั้งสี่ล็อกบริการแล้ว
- หลังยืนยันออนไลน์ยังใช้ redirect เดิมใน PR นี้ PR-3 จะพาเข้าบัตรที่ทราบหมวดห้องจริง

## PR-8: เอฟเฟกต์หมึกซึมกระดาษ

ที่ผู้ใช้ขอ: ลากเมาส์แล้วมีสีน้ำซึมกระดาษที่ปลายเมาส์ · กดเลือกหัวข้อใด หมึกหลายสีซึมลงกระดาษที่หัวข้อนั้น

ไฟล์ใหม่: `static/js/ink_bleed.js`, `static/css/ink_bleed.css` (ไม่ใช้ไลบรารีภายนอก ไม่มี inline script)

1. **รอยหมึกตามเมาส์**: `<canvas>` เต็มจอ `position:fixed; pointer-events:none; mix-blend-mode:multiply` อยู่ใต้เนื้อหา
   - ทำงานเฉพาะ `pointerType === "mouse"` จอสัมผัสไม่มีรอยตามนิ้ว
   - แต่ละหยด: วงไล่สีขอบฟุ้ง รัศมีเริ่ม 6–10px ขยายช้า ๆ ถึง 28–40px ขอบไม่เรียบ (สุ่มรัศมีย่อย 3–4 วงซ้อน) ค่อย ๆ จางใน 1.2–1.8 วินาที
   - ความทึบสูงสุด 0.10 ต่อหยด · หยดพร้อมกันไม่เกิน 60 · จำกัด devicePixelRatio ที่ 1.5 · หยุด `requestAnimationFrame` เมื่อไม่มีหยดหรือแท็บถูกซ่อน
2. **หมึกซึมเมื่อกดเลือก**: องค์ประกอบที่มี `data-ink` (แฟ้มบริการ, ชิปวัน/เวลา, รายการเมนู, วันในปฏิทิน)
   - ตอนกด: หมึก 3–4 สีเริ่มจากจุดที่กด แผ่ออกแบบขอบฟุ้ง ถูกตัดขอบตามรูปร่างองค์ประกอบ ใช้เวลา 600–800ms
   - หลังจบ: เหลือคราบจางค้างอยู่ตราบที่ยังถูกเลือก (`aria-current`, `:checked`) ความทึบคราบไม่เกิน 0.18
   - ชุดสีจากแถบสีแฟ้มบริการในธีม (เขียว น้ำเงิน เหลืองอำพัน แดง) อ่านจากตัวแปร CSS ของธีม ไม่ฝังรหัสสีใหม่
3. ข้อบังคับ:
   - `prefers-reduced-motion: reduce` = ปิดทั้งรอยเมาส์และแอนิเมชัน เหลือเฉพาะสถานะถูกเลือกแบบนิ่ง
   - ข้อความบนคราบหมึกต้องผ่านคอนทราสต์ 4.5:1 (ตรวจกับ CI accessibility gate เดิม)
   - ห้ามหน่วงการกด: การนำทาง/ส่งฟอร์มทำงานทันที หมึกเป็นแค่ภาพ
   - เปิดเฉพาะหน้าที่ `<body data-ink="on">`: เริ่มที่หน้าเลือกบริการและหน้าจองห้องสอนออนไลน์ หน้าเจ้าหน้าที่ไม่เปิด
   - HTMX สลับเนื้อหาแล้วเอฟเฟกต์ต้องยังทำงานกับองค์ประกอบใหม่ (ผูก event ที่ `document`)
4. test: Node test แบบเดียวกับ `tests/cassette-interaction.test.cjs` (reduced-motion = ไม่สร้าง canvas, เพดานจำนวนหยด, ไม่ทำงานกับ touch) + pytest ว่าหน้าเป้าหมายโหลดสคริปต์และมี `data-ink`
5. ภาพหน้าจอ + คลิปสั้น (ถ้าบันทึกได้): รอยเมาส์บนหน้าเลือกบริการ, หมึกซึมบนชิปเวลาที่ถูกเลือก, โหมด reduced-motion

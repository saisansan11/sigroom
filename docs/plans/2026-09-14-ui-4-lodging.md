# SIGROOM UI-4 Implementation Plan — Lodging Experience Redesign

## Status
`IMPLEMENTATION IN PROGRESS`

## Overview
Phase UI-4 focuses on establishing a modern, hotel-like, mobile-first lodging experience for SIGROOM while strictly preserving all V5.1 invariants:
- Bidirectional conflict checking across lodging cohorts and regular bookings.
- `is_active` controls student-portal open/closed state; `allocation_status` controls allocated/released lodging resources.
- Resource allocation mutations retain transaction/race protection.
- Authorization remains server-side.
- Public and student views strictly expose NO roommate PII (displaying only "ว่าง" vs "มีผู้เข้าพักแล้ว").
- Duplicate/normalized phone behavior and bed-range validation remain intact.
- Calendar lodging reservations retain non-clickable/background semantics.

This is a **presentation, accessibility, and user-experience improvement** phase with zero schema/database migrations.

---

## 1. Scope & Architecture

### Key Workstreams
1. **Public / Student Lodging Index (`lodging_index.html`)**:
   - Hotel-style listing of active lodging cohorts.
   - Clear dates, capacity metrics, remaining beds indicator.
   - Prominent single primary CTA (`เลือกห้องพัก →`).
   - Zero inline styles, responsive layout from 360px up to 1440px.

2. **Student Portal & Bed Selection (`student_portal.html`)**:
   - Hotel-like room cards with photo cover/gallery triggers.
   - Strict privacy: No roommate PII shown; beds display only "ว่าง" (available) or "มีผู้เข้าพักแล้ว" (occupied).
   - Sticky quick-jump button on mobile to jump to next available bed.
   - Bed selection modal with error retention (re-opens automatically on conflict/duplicate phone with preserved input values and inline error alert).
   - Room photo gallery modal with full keyboard navigation (`ArrowLeft`, `ArrowRight`, `Escape`), accessible focus management, and touch friendly buttons.

3. **Digital Key-Card Pass (`student_pass.html`)**:
   - Hotel-grade mobile key-card pass with 3D flip interaction (front: room/bed/student details; back: high-contrast check-in QR code).
   - Accessible flip toggle via click, touch, and keyboard (`Space`/`Enter`).
   - Roommates section displaying only occupied bed status (zero PII).
   - LINE share flow & quick clipboard copy with visual feedback.
   - Screenshot guidance for saving the pass locally on mobile.

4. **Check-In Verification Pass (`checkin.html`)**:
   - Dual-state verification interface:
     - **Authorized Staff / Supervisor**: Full verification pass with student details (Rank, Name, Unit, Phone, Room, Bed, Cohort), and action to confirm check-in.
     - **Public / Unauthorized**: Privacy-masked card showing only masked name (`_masked_student_label`), room, bed, and instructions to present to check-in duty staff.
   - Clear check-in confirmation status with timestamp and confirming officer name.

5. **Supervisor Lodging Management (`manage_list.html`)**:
   - Responsive layout adapting from single-column on mobile to dual-column on desktop.
   - Active cohorts list with live occupancy counters and status badges.
   - Create Cohort form with responsive date controls, clean room checklist, and touch-target friendly submit CTA.

6. **Cohort Detail & Occupant Roster (`cohort_detail.html`)**:
   - Prominent LINE and QR share banner with one-click copy and feedback.
   - High-level metric summary tiles.
   - Room-by-room occupancy breakdown.
   - Responsive master roster table (with horizontal scroll container to prevent mobile page breaking).
   - One-click Excel/CSV export for building management.

7. **Cohort Edit & Danger Zone (`cohort_edit.html`)**:
   - Clean form layout for editing cohort configuration and room assignments.
   - Dedicated **Force-Release Danger Zone** for superusers with clear warning styling, requiring explicit checkbox confirmation and reason when forcing room release.

8. **CSS Token & Component Architecture (`static/css/app.css`)**:
   - Consolidate lodging styles under `/* ===== UI-4 Lodging UX ===== */`.
   - Remove legacy inline styles across all lodging templates.
   - Ensure touch targets >= 44px, visible `:focus-visible` outlines, and `prefers-reduced-motion` compliance.

## 2. Invariants & Guardrails

- **Zero Schema Migrations**: `makemigrations --check --dry-run` must produce 0 changes.
- **Privacy Rule**: Public and student views never reveal roommate full names, ranks, units, or phone numbers.
- **Race Protection**: `select_for_update()` transaction locking in `lodging_book_bed` remains untouched.
- **Phone Normalization & Duplication**: `normalize_phone()` and cohort-level unique phone check remain active.
- **Server-Side Authorization**: `can_manage_cohort()` and `can_access_lodging_management()` checks remain enforced.

# SIGROOM — แผนพัฒนา (ทำคนเดียวร่วมกับ Claude Code / Codex)

เป้าหมาย: ระบบที่ **ใช้จริงได้ใน pilot 8 ห้อง** ภายในเครือข่ายภายใน โดยรักษาความถูกต้องของการถือครองห้องตาม SRS
แต่ตัดส่วนที่ต้องใช้ทีม (ASVS L2, pentest, coverage 90%, CI gate, LINE) ไปไว้หลัง pilot

หลักการทำงาน: **แต่ละ milestone ต้องรันได้และดูผลได้ด้วยตา** ก่อนขึ้น milestone ถัดไป
ถ้าติดขัดเกิน 1 ชั่วโมง ให้หยุดแล้วถาม Claude Code ว่า "ติดตรงนี้ ทำยังไงต่อ" ไม่ต้องพยายามแก้เอง

## สิ่งที่ต้องติดตั้งเอง (ครั้งเดียว)

| โปรแกรม | ทำไม | คำสั่ง (รันใน PowerShell แบบ Run as Administrator) |
|---|---|---|
| PostgreSQL 16 | ฐานข้อมูลที่รองรับ exclusion constraint | `winget install PostgreSQL.PostgreSQL.16` |

ระหว่างติดตั้งจะถามรหัสผ่านของผู้ใช้ `postgres` — จดไว้ แล้วใส่ใน `.env`

## Milestones

### M0 — โครงโปรเจค + โมเดลหลัก ✅ (Claude วางให้แล้ว)
- โปรเจค Django, settings, `.env`, แอป `accounts` `resources` `bookings`
- โมเดล: User (อีเมล @signalschool.ac.th), Unit, Resource, ResourceRule, ResourceApprover, Booking, BookingResource
- **ExclusionConstraint กันจองซ้อน** ที่ฐานข้อมูล
- Django Admin สำหรับทะเบียนห้อง/กฎ/ผู้ใช้
- **ดูผล:** `uv run manage.py runserver` → เปิด http://127.0.0.1:8000/admin เพิ่มห้องได้

### M1 — ฐานข้อมูลจริง + ทดสอบกันจองซ้อน ✅ (24 ส.ค. 2569)
- PostgreSQL 16 ติดตั้งแล้ว (รหัสผ่านเริ่มต้น `postgres` — **ต้องเปลี่ยนก่อน M6** ดูด้านล่าง)
- ฐานข้อมูล `ogn_room` + migrate + `btree_gist` + exclusion constraint ใช้งานจริง
- `uv run pytest` → 9/9 ผ่าน (ชนเวลา, ติดกันไม่ชน, buffer, ยกเลิกแล้วว่าง, อุปกรณ์ชน, นโยบายอนุมัติ)
- บัญชีผู้ดูแล `admin` + ข้อมูล pilot จาก `uv run manage.py seed_pilot` (5 หน่วย, 8 ห้อง, อุปกรณ์ 2)
- **ดูผล:** `uv run manage.py runserver` → http://127.0.0.1:8000/admin → ทรัพยากร (ห้อง/อุปกรณ์)

**ค้างจาก M1 — ทำก่อนเริ่ม pilot (M6):**
1. เปลี่ยนรหัสผ่าน `postgres` ใน PowerShell:
   `& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "\password"` (ถามรหัสเดิม `postgres` แล้วให้ตั้งใหม่) → แก้ `DB_PASSWORD` ใน `.env` ให้ตรง
2. จำกัด PostgreSQL ให้รับเฉพาะเครื่องตัวเอง: แก้ `listen_addresses = 'localhost'` ใน
   `C:\Program Files\PostgreSQL\16\data\postgresql.conf` แล้ว restart service `postgresql-x64-16`
3. เปลี่ยนรหัสผ่านบัญชี `admin` ของเว็บใน Admin → ผู้ใช้ → admin → เปลี่ยนรหัสผ่าน

### M2 — หน้าปฏิทินและจองห้อง (ผู้ขอใช้) ✅ (24 ส.ค. 2569)
- เข้าสู่ระบบ · ปฏิทินรายวัน/สัปดาห์/เดือน (FullCalendar) · ค้นห้องว่าง (FR-01/02)
- ฟอร์มจอง (ฟิลด์ตาม SRS 12.2) · แก้ไข/ยกเลิกของตนเองก่อนเส้นตาย (FR-04)
- การมองเห็น: คนทั่วไปเห็น "ไม่ว่าง + หน่วย" (D9)
- **ดูผล:** ใช้ 2 บัญชี จองจากบัญชีแรก ดูจากบัญชีที่สองเห็นแค่ "ไม่ว่าง"
- ผลตรวจ: เทส M1 เดิม 9 ข้อ + M2 ใหม่ 10 ข้อผ่านครบ · Django check ผ่าน · ไม่มี migration ค้าง

### M3 — อนุมัติ ✅ (24 ส.ค. 2569)
- นโยบายรายห้อง อัตโนมัติ/ต้องอนุมัติ (D1) · หน้ารออนุมัติของผู้อนุมัติ · อนุมัติ/ปฏิเสธพร้อมเหตุผล (FR-18, FR-24)
- ผู้รักษาการแทน (FR-20) · SLA/เร่งด่วน/หมดอายุ ด้วย `run_jobs` (FR-21–23)
- แจ้งเตือนในระบบ (กระดิ่ง) — ยังไม่ทำ LINE
- **ดูผล:** จองห้องประชุม → บัญชีผู้อนุมัติเห็นรายการ → กดอนุมัติ → ผู้จองเห็นสถานะเปลี่ยน

### M4 — จองเป็นชุด + ปฏิทินส่วนกลาง + งดใช้ห้อง
- BookingSeries (FR-13–17) · Blackout ตามขอบเขต (FR-11) · ResourceOutage (FR-12)
- **ดูผล:** จองทุกวันจันทร์ 1 ภาคเรียน ระบบแสดงครั้งที่ชนให้เลือกข้าม

### M5 — แก้ไขหลังอนุมัติ (Amendment) + บังคับย้าย
- BookingAmendment ตาม FR-34–38 และ P1 ทั้ง 3 ข้อ (ชุดปลายทางครบ, constraint ครบ, base_revision + FOR UPDATE)
- Preemption ตาม FR-25–30
- **ดูผล:** ขอแก้เวลาแล้วผู้อนุมัติปฏิเสธ → การจองเดิมยังอยู่

### M6 — no-show, รายงาน, audit log, สำรองข้อมูล → เริ่ม pilot
- สถานะการใช้งาน (ข้อ 9) · รายงานพื้นฐาน (ข้อ 13) CSV · audit log append-only (NF-01/02)
- สคริปต์ `pg_dump` รายวัน + ทดสอบกู้คืน 1 ครั้ง (NF-04)
- ติดตั้งบนเครื่องในหน่วย (LAN) · สร้างบัญชี 30–50 คน · เริ่ม pilot 1 เดือน

### หลัง pilot (ไม่อยู่ในแผนนี้)
LINE, 2FA, เปิดอินเทอร์เน็ต, QR check-in, เชื่อม AD — ตัดสินใจจากผล pilot ว่าจะทำเองต่อหรือใช้ SRS เป็น TOR จ้าง

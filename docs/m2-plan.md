# SIGROOM — แผน M2: หน้าปฏิทินและจองห้อง (ผู้ขอใช้)

สถานะ: **พัฒนาเสร็จและตรวจรับทางเทคนิคแล้ว (24 ส.ค. 2569)**
อ้างอิง: `CLAUDE.md` (กติกา), `docs/room-booking-srs.html` (FR/D ที่อ้าง), `docs/build-plan.md`

## 0. เป้าหมายและขอบเขต

ผู้ขอใช้ (อาจารย์/เจ้าหน้าที่) เข้าสู่ระบบ → เห็นปฏิทินห้อง → เลือกเวลา → เห็นห้องว่าง → จอง → ดู/แก้/ยกเลิกของตนเอง
โดยคนอื่นเห็นเพียง "ไม่ว่าง + หน่วย" ทุกอย่างผ่าน `bookings/services.py` และ exclusion constraint ที่มีอยู่แล้ว

**ทำใน M2:** FR-01, FR-02, FR-03, FR-04, FR-06 (1 ห้อง + อุปกรณ์หลายชิ้น), FR-07/08 (buffer แสดงจาง), D1 (อัตโนมัติ/รออนุมัติ), D9 + SR-07 (การมองเห็น), D11 (90 วัน / 4 ชม.), กฎรายห้อง (เวลาให้บริการ, ระยะขั้นต่ำ/สูงสุด, หน่วยที่จองได้, ความจุเตือนไม่บล็อก)
**ไม่ทำใน M2:** อนุมัติ/ปฏิเสธ (M3), จองเป็นชุด (M4), แก้ไขหลังอนุมัติแบบ amendment และบังคับย้าย (M5), แจ้งเตือน, รายงาน, no-show
**ข้อจำกัดชั่วคราวของ M2:** การจองที่ส่งแล้ว (รออนุมัติ/อนุมัติ) แก้ได้เฉพาะฟิลด์กลุ่ม (ค) ตาม FR-05 — ชื่อกิจกรรม ผู้รับผิดชอบ จำนวนคน จัดโต๊ะ หมายเหตุ — ส่วนการแก้ **เวลา/ห้อง/อุปกรณ์** ให้ "ยกเลิกแล้วจองใหม่" พร้อมข้อความบอกว่าระบบขอแก้ไขจะมาในรุ่นถัดไป (ร่างแก้ได้ทุกอย่าง)

## 2. สเปกเทคนิค (สำหรับ Codex)

### 2.1 แบบจำลองข้อมูล (เพิ่ม — migration แบบ expand เท่านั้น)
- `Booking.equipment = ManyToManyField("resources.Resource", blank=True, limit_choices_to={"resource_type": "equipment"}, related_name="bookings_as_equipment")`
  เก็บ "อุปกรณ์ส่วนกลางที่ขอ" เพื่อใช้ตอนแก้ไข/แสดงผล · ช่วงถือครองจริงยังสร้างจาก `services.place_holds(booking, equipment=list(booking.equipment.all()))`
- ห้ามแก้ `BookingResource` และ constraint ที่มีอยู่

### 2.2 services (`bookings/services.py`) — เพิ่มฟังก์ชัน
| ฟังก์ชัน | ทำอะไร | อ้าง |
|---|---|---|
| `validate_booking_window(resource, start, end, user, now=None)` | คืน list ข้อความผิดพลาดภาษาไทย: นอกเวลาให้บริการ, สั้น/ยาวกว่ากำหนด, ล่วงหน้าเกิน `max_advance_days`, เวลาเริ่มอยู่ในอดีต, ไม่อยู่บนช่วง 15 นาที, หน่วยไม่อยู่ใน `allowed_units`, ห้องสถานะไม่ใช่ `active` | ข้อ 5, D11, SRS 12.2 |
| `find_available_rooms(start, end, user, attendees=None, equipment_codes=())` | คืน 2 รายการ: ห้องว่างและมีสิทธิ์ (พร้อม `capacity_warning` bool) / ห้องไม่ว่างหรือไม่มีสิทธิ์ (พร้อมเหตุผล) โดย "ไม่ว่าง" ต้องคำนวณจาก `BookingResource` ที่ `released_at IS NULL` และ hold ซ้อนกับช่วง **ที่รวม buffer ของห้องนั้น** (ใช้ `compute_hold`) และรวมสถานะอุปกรณ์ที่ขอด้วย | FR-01, FR-07 |
| `cancel_booking(booking, user, now=None)` | ตรวจสิทธิ์ (ผู้จอง/superuser) และเส้นตาย `cancel_cutoff_hours` → ตั้ง `CANCELLED`, `release_holds`, `revision += 1` · เกินเส้นตาย → `PermissionError` พร้อมข้อความและผู้ดูแลห้อง | FR-04, FR-10 |
| `can_view_details(user, booking) -> bool` และ `calendar_label(user, booking) -> str` | ผู้จอง, คนหน่วยเดียวกัน, ผู้อนุมัติ/เจ้าหน้าที่ของห้องนั้น, superuser, `is_infosec_officer` → เต็ม · อื่น ๆ: normal → "ไม่ว่าง — <หน่วย>", restricted/sensitive → "ไม่ว่าง" · sensitive: ผู้อนุมัติ/เจ้าหน้าที่ห้องเห็นแบบปกปิดชื่อ (วัน เวลา จำนวนคน อุปกรณ์ จัดโต๊ะ) | D9, SR-07 (P2) |
| `frequent_values(unit, field)` | ค่าที่ไม่ซ้ำ 10 ค่าล่าสุดของหน่วยสำหรับ datalist: `title`, `responsible_name`, `responsible_phone`, `attendee_level`, `layout` | กติกา 7 |
| `editable_fields(booking)` | ร่าง → ทุกฟิลด์ · รออนุมัติ/อนุมัติ → เฉพาะกลุ่ม (ค): `title, responsible_name, responsible_phone, attendees, attendee_level, layout, fixed_equipment_needed, note` (จำนวนคนเกินความจุเตือนไม่บล็อก) | FR-05 |
- `submit_booking` เดิม: เพิ่มเรียก `validate_booking_window` ก่อน และตั้ง `is_urgent` ถ้า policy = REQUIRED และเวลาเริ่มห่างน้อยกว่า 2 วันทำการ + 24 ชม. (นับวันทำการ = จันทร์–ศุกร์ ยังไม่มีปฏิทินส่วนกลาง) — M3 จะใช้ต่อ (FR-23)

### 2.4 ฟอร์ม (`bookings/forms.py`)
- `BookingForm(ModelForm)` ฟิลด์ตาม S4 · `unit` ค่าเริ่มต้นจาก `user.unit` และจำกัดตัวเลือกเป็นหน่วยของผู้ใช้ + หน่วยลูก (ถ้า superuser = ทุกหน่วย)
- `date/start/end` เป็นฟิลด์แยก (`DateField` + `TimeField` เลือกจาก `<select>` ช่วง 15 นาที 07:00–21:00) แล้ว `clean()` ประกอบเป็น `start_at/end_at` ใน timezone Asia/Bangkok
- datalist: `title, responsible_name, responsible_phone, attendee_level, layout` ใช้ `frequent_values` + (layout) รายการของห้อง
- `fixed_equipment_needed`: checkbox จาก `room.fixed_equipment` บรรทัดละรายการ + ช่องพิมพ์เพิ่ม → เก็บรวมเป็นข้อความบรรทัดละรายการ
- วันที่แสดง/รับเป็น **พ.ศ.** (`dd/mm/yyyy` พ.ศ.) — เขียน `templatetags/thaidate.py` มี filter `thai_date`, `thai_datetime` และฟอร์มแปลง พ.ศ. ↔ ค.ศ.

### 2.7 เทสที่ต้องผ่าน (`bookings/tests_m2.py`, pytest + Django test client)

4. POST ส่งคำขอผ่าน client สำเร็จ → สถานะอนุมัติ, มี hold, redirect ไป S5
5. POST ส่งคำขอชน → status 200 กลับฟอร์ม มีข้อความชน ไม่มี booking ค้างในสถานะ pending/approved
6. `cancel_booking` ก่อนเส้นตาย → CANCELLED + hold ปลด · หลังเส้นตาย (เริ่มใน 2 ชม.) → PermissionError
7. การมองเห็น: บัญชีต่างหน่วยเปิด `/bookings/<id>/` ได้หน้าปกปิด ไม่มีชื่อกิจกรรมใน HTML · `calendar_events` คืน title "ไม่ว่าง — แผนกวิชาการสื่อสาร" สำหรับ normal และ "ไม่ว่าง" สำหรับ restricted
8. แก้ไขหลังอนุมัติ: POST เปลี่ยน `start_at` ผ่าน `/edit/` ต้องถูกเพิกเฉย (ไม่เปลี่ยน) แต่เปลี่ยน `title` ได้ และ `revision` เพิ่ม
9. `is_urgent` ตั้งเป็น True เมื่อจองห้องต้องอนุมัติล่วงหน้า 30 ชม.

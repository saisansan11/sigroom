# แผนพัฒนา V7 — จองครบวงจรทุกประเภทห้อง: ง่าย เร็ว จบใน 3 คลิก

เป้าหมายจากเจ้าของระบบ: ให้ SIGROOM เป็นระบบจอง **ห้องพัก · ห้องสอนออนไลน์ · ห้องเรียน/ประชุม
แบบครบวงจรในที่เดียว** ที่ทุกคนใช้เป็นภายในไม่กี่นาที — เปิดเว็บ เลือก คลิกไม่กี่ครั้ง จองสำเร็จ

เอกสารนี้เป็นแผนงานสำหรับ agent ผู้พัฒนา โดยมี Claude เป็นผู้ตรวจรับ และเจ้าของระบบอนุมัติขั้นสุดท้าย
ทำทีละงาน **ห้ามข้ามลำดับ ห้ามรวบหลายงานใน PR เดียว** ผู้รับงานต้องอ่าน `CLAUDE.md` ก่อนเริ่มเสมอ

## ตัวชี้วัดความสำเร็จของ V7 (วัดจริงตอนปิดเวอร์ชัน)

| ตัวชี้วัด | เป้า | วิธีวัด |
|---|---|---|
| จำนวนคลิกจากหน้าแรก → ยืนยันจองสำเร็จ (กรณีปกติ) | ≤ 3 คลิก | ไล่นับเองบนมือถือ ทุกประเภทห้อง |
| เวลาที่ผู้ใช้ใหม่ (ไม่เคยใช้ระบบ) จองครั้งแรกสำเร็จ | ≤ 2 นาที | จับเวลาผู้ทดลองจริง 3 คน |
| ทุกหน้าหลักใช้บนมือถือ 360px ได้ ไม่มีส่วนล้นจอ | 100% | ตรวจด้วย browser + ภาพหน้าจอ |
| เทสทั้งหมดผ่าน | 100% | `uv run pytest` |

## กติกา workflow (สืบทอดจากแผน V6 ข้อ 0 ทั้งหมด — สรุปซ้ำเฉพาะที่ต้องจำ)

1. Branch `feat/lodging-v5-2` คือ production (Cloud Build auto-deploy) — **ห้าม push ตรงเด็ดขาด**
2. พัฒนาบน branch แยกตามงาน: `feat/v7-a-onestop`, `feat/v7-b-online`, `feat/v7-c-fast`, `feat/v7-d-pwa`
3. ก่อนเปิด PR: `uv run pytest` ผ่านทุกตัว · `manage.py check` ไม่มี issue ·
   `makemigrations --check --dry-run` ไม่มี migration ตกค้าง
4. PR ที่มี migration: pipeline B0 (build → migrate → deploy) มีแล้ว — ระบุใน PR ว่ามี migration
   และหลัง merge ตรวจ Cloud Build → History ว่าผ่านครบ 3 ขั้น
5. เจ้าของระบบสั่ง **"merge PR #..."** ชัดเจนเท่านั้นจึง merge ได้
6. กฎธุรกิจอยู่ใน `services.py` เท่านั้น · ข้อความผู้ใช้เป็นไทย/พ.ศ. · schema แบบ expand/contract
7. ห้ามเริ่มงานถัดไปก่อนงานปัจจุบันถูก merge — ติดคำถามเชิงออกแบบให้ถามใน PR

## งาน A — หน้าแรกแบบ One-Stop: "วันนี้จะใช้ห้องแบบไหน" (ไม่มี migration)

**ปัญหา:** ทางเข้าแต่ละประเภทกระจายอยู่ในเมนู (ปฏิทิน / จองห้อง / จองห้องพัก) ผู้ใช้ใหม่ไม่รู้จะเริ่มตรงไหน
และต้องกรอกฟอร์มค้นหาก่อนจึงเห็นห้องว่าง

**ให้ทำ:**
1. ปรับหน้าแรก (หลัง login และหน้า guest) เพิ่มส่วนบนสุดเป็น **การ์ดทางเข้า 4 ใบ** ปุ่มใหญ่กดง่ายบนมือถือ:
   - ห้องเรียน/ห้องสอนปฏิบัติ (`classroom` + `lab`)
   - ห้องประชุม (`meeting` + `special`)
   - ห้องสอนออนไลน์ (`online` — เปิดใช้จริงเมื่องาน B merge; ก่อนหน้านั้นซ่อนการ์ดอัตโนมัติถ้าไม่มีห้องหมวดนี้)
   - ห้องพักหลักสูตร (ลิงก์ไป lodging index เดิม)
2. ใต้การ์ด: แถบ **"ว่างตอนนี้ — จองเลย"** ต่อหมวด แสดงห้องที่ว่างในชั่วโมงถัดไป (สูงสุด 4 ห้อง/หมวด
   พร้อมรูปหน้าปกจาก V6-C) ปุ่ม "จองเลย" พาเข้าฟอร์มจองแบบ **prefill** วันนี้ + ชั่วโมงถัดไปให้เสร็จ
   ผู้ใช้เหลือแค่กรอกชื่อกิจกรรมแล้วกดยืนยัน = ครบ 3 คลิก (การ์ดหมวด → จองเลย → ยืนยัน)
3. ตรรกะ "ห้องที่ว่างในชั่วโมงถัดไป" เขียนใน `bookings/services.py` (ฟังก์ชันใหม่ ห้ามเขียนใน view)
   ใช้การตรวจชนเดิม — ห้ามเขียนเงื่อนไขชนซ้ำใหม่
4. การ์ดหมวดใช้จำนวนห้องจริงจากฐานข้อมูล (`Resource.Category`) ไม่ hardcode
5. CSS เพิ่มใน `static/css/app.css` ตามธีม Tactical HUD เดิม — ห้าม inline style

**เทส:** service "ว่างตอนนี้" (ว่างจริง/ตัดห้องที่ชน/ตัดห้องงดใช้/จำกัดจำนวน) · view หน้าแรกมี context ครบหมวด ·
ลิงก์จองเลยแนบ query prefill ถูกต้อง

**ดูผล:** เปิดหน้าแรกบนมือถือ → เห็นการ์ด 4 ใบ + ห้องว่างตอนนี้ → กด "จองเลย" → ฟอร์มถูกเติมวัน-เวลาให้แล้ว

## งาน B — หมวดใหม่ "ห้องสอนออนไลน์" (มี migration — expand)

**ปัญหา:** ระบบยังไม่รู้จักห้องสอนออนไลน์/สตูดิโอบันทึกการสอน ทั้งที่เป็นความต้องการหลักของ V7

**ให้ทำ:**
1. เพิ่ม `Resource.Category.ONLINE = "online", "ห้องสอนออนไลน์"` (choices เปลี่ยน → migration เล็ก 1 ไฟล์)
2. เพิ่มฟิลด์ `Booking.online_meeting_url` (URLField, blank) — ลิงก์ห้องเรียนออนไลน์ของครั้งนั้น:
   - แสดงในฟอร์มจอง **เฉพาะเมื่อห้องเป็นหมวด online** (เงื่อนไขใน template/form ไม่ใช่ JS ซับซ้อน)
   - แสดงในหน้ารายละเอียดการจองแก่ผู้จอง/ผู้อนุมัติ/เจ้าหน้าที่ · ผู้ใช้ทั่วไปที่เห็นแบบ masked ต้องไม่เห็นลิงก์
   - แนบลิงก์ไปกับข้อความแจ้งเตือนเมื่ออนุมัติแล้ว (ใช้ notify เดิม)
3. `seed_pilot` เพิ่มห้องตัวอย่าง 2 ห้อง: `STU-ONLINE-1` "สตูดิโอสอนออนไลน์ 1" (นโยบาย AUTO,
   buffer หลังใช้ 15 นาที, อุปกรณ์: กล้อง/ไมค์/ไฟสตูดิโอ/จอเขียว) และ `STU-ONLINE-2`
4. รายงานสรุปการใช้ (S16) ต้องรวมหมวดใหม่โดยไม่ต้องแก้อะไรเพิ่ม — ตรวจยืนยัน ถ้ามี hardcode หมวดให้แก้เป็นวนตาม choices
5. ห้ามแตะกฎกันจองซ้อน — หมวดใหม่ใช้ ExclusionConstraint เดิมโดยอัตโนมัติ

**เทส:** จองห้อง online พร้อมลิงก์ → ลิงก์แสดงแก่ผู้จอง, ไม่แสดงในมุมมอง masked · ฟอร์มห้องหมวดอื่นไม่มีช่องลิงก์ ·
migration รันแล้วข้อมูลเดิมไม่กระทบ

**ดูผล:** จอง STU-ONLINE-1 ใส่ลิงก์ Google Meet → เปิดด้วยบัญชีอื่นเห็นแค่ "ไม่ว่าง" ไม่เห็นลิงก์

## งาน C — จองให้ไวขึ้นอีก: จองซ้ำ + ช่วงเวลาสำเร็จรูป (มี migration เล็ก — expand)

**ปัญหา:** ผู้ใช้ประจำ (ครูสอนวิชาเดิมทุกสัปดาห์) ยังต้องกรอกฟอร์มเดิมซ้ำทุกครั้ง และการพิมพ์เวลาเริ่ม-สิ้นสุด
เป็นจุดที่ช้าที่สุดบนมือถือ

**ให้ทำ:**
1. **ปุ่ม "จองแบบเดิมอีกครั้ง"** ในหน้า "การจองของฉัน" ทุกใบที่จบแล้ว/อนุมัติแล้ว →
   เปิดฟอร์มจองห้องเดิมพร้อม prefill ทุกช่องจากครั้งก่อน (ยกเว้นวันที่ — ให้ default วันพรุ่งนี้ เวลาเดิม)
   ตรวจชน/กฎทุกอย่างเดินตามปกติ ไม่มีทางลัดข้ามกฎ
2. **ช่วงเวลาสำเร็จรูป:** แถวปุ่มเหนือช่องเวลาในฟอร์มจอง — "คาบเช้า 0800-1200" · "คาบบ่าย 1300-1600" ·
   "ทั้งวัน 0800-1600" กดแล้วเติม start/end ให้ (JS เล็ก ๆ ใน template ได้ เพราะเป็นตัวช่วยกรอก ไม่ใช่กฎธุรกิจ)
   ช่วงเวลาแก้ไขได้ใน Django Admin ผ่าน `ReferenceValue` เดิม (field ใหม่ `time_preset` ค่าเช่น `0800-1200|คาบเช้า`)
3. **ห้องโปรด:** M2M `User.favorite_resources` (migration expand 1 ไฟล์) — ปุ่มดาวบนการ์ดห้อง
   ในหน้าค้นหา/หน้าแรก ห้องโปรดขึ้นก่อนเสมอในผลค้นหาและแถบ "ว่างตอนนี้" ของงาน A

**เทส:** rebook prefill ครบและตรวจชนยังทำงาน · time_preset แสดงตามลำดับ/ปิดใช้ได้ ·
ห้องโปรดเรียงก่อนและติด-ถอนดาวได้เฉพาะของตนเอง

**ดูผล:** จองวิชาเดิมสัปดาห์ถัดไปด้วย 2 คลิก (จองแบบเดิม → ยืนยัน)

## งาน D — ติดเครื่องทุกคน: PWA + ตรวจมือถือรวบยอด (ไม่มี migration)

**ปัญหา:** ผู้ใช้ต้องพิมพ์ URL หรือหา bookmark ทุกครั้ง — "ทุกคนใช้งานสะดวก" ต้องให้ SIGROOM
อยู่บนหน้าจอโฮมมือถือเหมือนแอป

**ให้ทำ:**
1. `manifest.webmanifest` (ชื่อ SIGROOM, ไอคอน 192/512 สร้างจากโลโก้เส้นสัญญาณเดิม, theme color ตามธีม,
   `display: standalone`, `start_url: /`) + `<link rel="manifest">` และ meta iOS ใน `base.html`
2. ยังไม่ทำ service worker/offline (เว็บต้องออนไลน์ถึงจองได้จริง — อย่าสร้างความเข้าใจผิดว่า offline ได้)
3. คำแนะนำ "ติดตั้งลงหน้าจอโฮม" ในเมนูบัญชี (วิธีสำหรับ Android/iPhone อย่างละ 3 ขั้น ภาษาไทย)
4. ตรวจรวบยอดทุกหน้าหลักที่ 360px: หน้าแรกใหม่ (งาน A), ฟอร์มจอง (งาน B–C), portal ห้องพัก, key card —
   เก็บภาพหน้าจอแนบ PR

**เทส:** manifest เสิร์ฟได้ (HTTP 200, content-type ถูก) · base.html มีลิงก์ manifest

**ดูผล:** เปิดเว็บบนมือถือ → เมนู "เพิ่มลงหน้าจอโฮม" → ไอคอน SIGROOM ขึ้นบนหน้าจอ เปิดแล้วไม่มีแถบ URL

## ลำดับการทำและการส่งมอบ

1. งาน A → PR → Claude ตรวจ → เจ้าของสั่ง merge → ดูผลบนเว็บจริง
2. งาน B → PR (มี migration — ตรวจ Cloud Build ครบ 3 ขั้นหลัง merge) → ดูผลบนเว็บจริง

4. งาน D → PR → ดูผล → **วัดตัวชี้วัดทั้ง 4 ข้อ** → ปิด V7
